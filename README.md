# 🏠 居委会排班表 · 纯净开源版

> 一个适合 **居委会、社区、办公室、物业值班、活动值守** 等场景使用的单文件 HTML 排班工具。  
> 打开浏览器即可使用，不需要安装软件，不需要数据库，也不需要服务器。

---

## 📌 项目简介

**居委会排班表 · 纯净开源版** 是一个基于 HTML / CSS / JavaScript 制作的本地排班工具。

它的特点是：

- ✅ 单文件运行，下载后双击即可打开
- ✅ 支持 WPS / Office / Excel 表格复制导入
- ✅ 支持自动排班、手动修改、请假记录、冲突检查
- ✅ 支持节假日 / 调休 API 导入
- ✅ 支持打印、导出 CSV、导出 JSON 备份
- ✅ 支持飞书 / 钉钉机器人推送
- ✅ 适合发布到 GitHub Pages / Cloudflare Pages
- ✅ 纯净开源版不内置真实隐私数据

本项目适合给不熟悉复杂办公系统的人使用，尤其适合只需要一个轻量、直观、可打印、可备份的排班工具的场景。

## 🧼 纯净开源版说明

本仓库版本为 **纯净开源版**。

已经清空或不内置以下敏感内容：

- 不内置真实人员信息
- 不内置真实联系电话
- 不内置真实地址
- 不内置真实请假记录
- 不内置真实排班数据

## ✨ 功能特点

### 👥 人员管理

支持对值班人员进行管理：

- 添加人员
- 编辑人员
- 启用人员
- 停用人员
- 删除人员
- 批量导入人员

人员信息可填写：

- 姓名
- 职务
- 负责小区
- 联系电话

> 提醒：公开发布到 GitHub 时，不建议在源码里写入真实人员信息。

---

### 🧠 WPS / Office / Excel 排班顺序学习

如果你以前已经有 WPS、Excel 或 Office 排班表，可以直接复制旧表格内容，让系统学习原有排班顺序。

例如旧排班表中是：

```text
日期        班次        值班人员
2026-05-01  节假日值班  张三
2026-05-02  周末白班    李四
2026-05-03  周末白班    王五
2026-05-04  工作日晚班  赵六
```

系统可以学习出人员轮转顺序：

```text
张三 → 李四 → 王五 → 赵六
```

后续自动排班时，就可以按照这个顺序继续生成。

---

### ✨ 自动排班

支持一键自动生成本月排班。

自动排班支持：

- 按人员列表顺序排班
- 按 WPS / Office 学习顺序排班
- 按不同班次分别轮转
- 自动避开请假人员
- 自动避开停用人员
- 生成前先预览
- 确认后再应用

这样可以避免一键覆盖导致误操作。

---

### 📅 节假日 / 调休 API 导入

支持通过 API 自动导入某一年的节假日和调休数据。

默认 API 示例：

```text
https://timor.tech/api/holiday/year/{year}
```

其中 `{year}` 会自动替换成你填写的年份。

例如填写：

```text
2026
```

系统会请求：

```text
https://timor.tech/api/holiday/year/2026
```

导入后，系统会自动区分：

- 法定假日
- 休息日
- 调休补班

并根据这些信息调整排班类型。

---

### 🩺 请假记录与冲突提示

支持添加请假记录：

- 请假人员
- 开始日期
- 结束日期
- 请假原因

如果某人请假当天仍然被安排值班，日历中会出现冲突提示。

---

### ⚠️ 一键修复冲突

如果出现以下情况：

- 值班人员当天请假
- 值班人员已停用
- 自动排班后产生冲突

可以点击：

```text
⚠️ 修复冲突
```

系统会尝试自动更换为其他可排班人员。

如果没有合适人员，系统会清空当天排班，等待人工处理。

---

### 📥 导入排班

支持从 WPS / Office / Excel 复制表格后粘贴导入。

推荐表格格式：

```text
日期 | 星期 | 班次 | 值班人员 | 备注
```

示例：

```text
2026-05-01 | 周五 | 节假日值班 | 张三 | 劳动节
2026-05-02 | 周六 | 周末白班 | 李四 |
2026-05-03 | 周日 | 周末白班 | 王五 |
```

---

### 📤 导出与备份

支持导出：

- CSV 排班表
- JSON 完整备份

CSV 适合用 WPS / Excel 打开。  
JSON 适合完整备份和恢复。

JSON 备份通常包含：

- 居委会信息
- 人员信息
- 排班数据
- 节假日数据
- 请假记录
- 推送配置
- 操作日志

---

### 🖨️ 打印排班表

支持多种打印模板：

- 简洁版：只显示日期和值班人员
- 标准版：显示日期、班次和值班人员
- 归档版：显示日期、班次、值班人员和备注

打印时会自动隐藏按钮、侧边栏和操作区域。

推荐打印设置：

```text
纸张：A4
方向：横向
缩放：适合页面 / 90%
```

---

### 🔔 飞书 / 钉钉推送

支持通过 Cloudflare Worker 中转推送到飞书 / 钉钉。

推荐结构：

```text
排班表 HTML → Cloudflare Worker → 飞书 / 钉钉机器人
```

不建议在前端 HTML 中直接写真实 Webhook。

推送支持：

- 普通文本
- 表格文本
- Markdown 表格
- 飞书卡片表格

如果使用飞书，推荐使用：

```text
飞书卡片表格
```

如果使用钉钉，推荐使用：

```text
Markdown 表格
```

系统会记录一些关键操作，例如：

- 添加人员

## 🚀 快速开始

### 方法一：直接打开使用

下载本项目后，双击打开：

```text
index.html
```

推荐浏览器：

- Microsoft Edge
- Google Chrome
- Chromium
- Firefox
- 360 极速浏览器

国产系统如银河麒麟、统信 UOS 等，只要能使用现代浏览器，也可以打开使用。

---

### 方法二：发布到 GitHub Pages

适合想要在线访问的人。

操作步骤：

1. 新建 GitHub 仓库
2. 上传 `index.html` 和 `README.md`
3. 打开仓库 `Settings`
4. 找到 `Pages`
5. Source 选择：

```text
Deploy from a branch
```

6. Branch 选择：

```text
main
```

7. 目录选择：

```text
/root
```

8. 保存后等待部署完成

访问地址通常类似：

```text
https://你的用户名.github.io/仓库名/
```

---

### 方法三：发布到 Cloudflare Pages

适合想要用 Cloudflare 托管的人。

简单步骤：

1. 打开 Cloudflare 后台
2. 进入 `Workers & Pages`
3. 创建 Pages 项目
4. 上传静态文件
5. 确保首页文件名为：

```text
index.html
```

6. 点击部署

部署完成后，Cloudflare 会给你一个访问地址。

```text
姓名
职务
```

点击人员旁边的编辑按钮，可以修改人员信息。

## 🔔 飞书 / 钉钉推送配置

### 为什么需要 Worker 中转？

不建议浏览器直接请求飞书 / 钉钉 Webhook。

原因：

1. 浏览器可能会遇到跨域限制
2. Webhook 写在前端不安全
3. 不方便统一管理推送格式

推荐使用 Cloudflare Worker 中转。

---

### 推送流程

```text
排班表 HTML
    ↓
Cloudflare Worker 中转接口
    ↓
飞书 / 钉钉机器人
```

---

### Worker 需要配置的 Secret

在 Cloudflare Worker 中配置：

```text
PUSH_TOKEN
FEISHU_WEBHOOK
DINGTALK_WEBHOOK
```

只用飞书时，可以只配置：

```text
PUSH_TOKEN
FEISHU_WEBHOOK
```

只用钉钉时，可以只配置：

```text
PUSH_TOKEN
DINGTALK_WEBHOOK
```

---

### 排班表里需要填写

打开排班表，点击：

```text
🔔 推送
```

填写：

```text
推送中转接口地址
推送平台
推送口令
推送格式
人员变动自动提醒
```

其中：

- 推送中转接口地址：你的 Cloudflare Worker 地址
- 推送平台：飞书 / 钉钉
- 推送口令：你设置的 PUSH_TOKEN
- 推送格式：飞书推荐“飞书卡片表格”，钉钉推荐“Markdown 表格”
- 人员变动自动提醒：开启后，人员变化会自动推送

## 🔒 数据安全与隐私提醒

本工具默认使用浏览器本地存储。

也就是说，数据一般保存在当前浏览器里，不是云数据库。

可能导致数据丢失的情况：

- 清理浏览器缓存
- 更换浏览器
- 更换电脑
- 使用无痕模式
- 手动重置数据
- 系统重装

正式使用时建议：

```text
每次大改排班前，先导出 JSON 备份
每次正式发布排班后，再导出 JSON 备份
```

## ❓ 常见问题

### 1. 打开后是空的，正常吗？

正常。  
纯净开源版默认不创建示例人员，需要自行添加或导入。

---

### 2. 数据保存在哪里？

保存在当前浏览器本地。

不是云端数据库，不会自动同步到其他电脑。

---

### 3. 换电脑后数据还在吗？

不在。  
需要先在旧电脑导出 JSON 备份，再到新电脑导入恢复。

---

### 4. 为什么飞书 / 钉钉推送失败？

可能原因：

- Worker 地址填写错误
- PUSH_TOKEN 填错
- Worker 没有部署成功
- 飞书 / 钉钉 Webhook 没有配置到 Worker Secret
- 机器人安全设置限制了关键词
- 网络无法访问 Cloudflare Worker

---

### 5. 为什么 WPS 导入识别失败？

建议检查表格是否包含：

```text
日期
班次
值班人员
```

如果表格很复杂，建议先整理成：

```text
日期 | 星期 | 班次 | 值班人员 | 备注
```

---

### 6. 为什么自动排班不符合预期？

请检查：

- 人员是否已添加
- 人员是否在岗
- 是否导入节假日
- 是否添加请假记录
- 是否学习了旧排班顺序
- 自动排班方式是否选择正确

---

### 7. 可以多人一起用吗？

当前版本不是真正的多人协同系统。

它更像是：

```text
在线打开的本地排班工具
```

多人使用时，每个人浏览器里的数据可能不同。

如果需要多人协同，需要后续接入云数据库和登录系统。

---

### 8. 可以在国产系统上使用吗？

可以。

银河麒麟、统信 UOS 等系统，只要有现代浏览器，一般都可以打开使用。

建议使用：

- Chromium
- Firefox
- 360 极速浏览器
- 系统自带现代浏览器
