# 🏠 居委会排班表 · 纯净开源版

> 一个适合 **居委会、社区、办公室、物业、活动值守、节假日值班** 等场景使用的单文件 HTML 排班工具。  
> 支持 **WPS / Office / Excel 导入、自动排班、请假冲突检测、节假日 API 导入、打印、导出备份、飞书 / 钉钉推送**。

---

## 📖 项目简介

**居委会排班表 · 纯净开源版** 是一个基于 **HTML + CSS + JavaScript** 制作的轻量级排班工具。

它不需要安装软件，不需要数据库，不需要后端服务器。下载后直接用浏览器打开 `index.html` 即可使用。

本项目最初是为了满足居委会、社区办公室等场景中的日常值班排班需求，适合处理以下情况：

- 工作日晚班排班
- 周末值班排班
- 法定节假日值班排班
- 调休补班排班
- 人员请假冲突处理
- WPS / Excel 旧排班表导入
- 打印纸质排班表
- 飞书 / 钉钉群推送排班信息

---

## 🧼 纯净开源版说明

本仓库为 **纯净开源版**，适合公开发布到 GitHub。

本版本已经清理以下敏感信息：

- 不内置真实人员姓名
- 不内置真实联系电话
- 不内置真实居委会地址
- 不内置真实书记 / 民警 / 工作人员信息
- 不内置真实值班安排
- 不内置真实请假记录
- 不内置飞书 Webhook
- 不内置钉钉 Webhook
- 不内置 Cloudflare Worker 推送口令
- 不自动生成默认示例人员

首次使用时，需要你自行添加人员，或者通过 WPS / Office / Excel / CSV 导入人员和排班。

> ⚠️ 如果你准备公开发布本项目，请不要把真实的 JSON 备份、真实排班表、Webhook、PUSH_TOKEN 等敏感内容上传到 GitHub。

## ✨ 功能特点

### 👥 人员管理

支持对值班人员进行基础管理：

- 添加人员
- 编辑人员
- 启用人员
- 停用人员
- 删除人员
- 批量导入人员

人员字段包括：

- 姓名
- 职务
- 负责小区
- 联系电话

人员可以设置为 **在岗** 或 **停用**。

- 在岗人员：参与自动排班
- 停用人员：不参与自动排班，但历史排班记录不会被立即删除

---

### 🧠 WPS / Office / Excel 排班顺序学习

如果你以前已经有 WPS、Excel 或 Office 版排班表，可以把旧排班表导入，让系统学习原有轮转顺序。

例如旧排班：

```text
日期        星期    班次        值班人员
2026-05-01  周五    节假日值班  张三
2026-05-02  周六    周末白班    李四
2026-05-03  周日    周末白班    王五
2026-05-04  周一    工作日晚班  赵六
```

系统可以学习出类似顺序：

```text
张三 → 李四 → 王五 → 赵六
```

后续自动排班时，可以根据学习到的顺序继续轮转。

支持学习：

- 通用排班顺序
- 工作日晚班顺序
- 周末白班顺序
- 节假日值班顺序
- 调休补班晚班顺序

---

### ✨ 自动排班

支持一键生成当月排班。

自动排班支持：

- 按人员列表顺序排班
- 按 WPS / Office 学习顺序排班
- 按不同班次分别轮转
- 自动避开请假人员
- 自动避开停用人员
- 生成前先预览
- 确认无误后再应用

自动排班不会直接强制覆盖当前内容，而是先生成预览，避免误操作。

---

### 📅 节假日 / 调休 API 导入

支持通过 API 导入节假日和调休数据。

默认 API 示例：

```text
https://timor.tech/api/holiday/year/{year}
```

其中 `{year}` 会自动替换为你输入的年份。

例如填写年份：

```text
2026
```

系统会请求：

```text
https://timor.tech/api/holiday/year/2026
```

导入后会自动识别：

- 法定假日
- 休息日
- 调休补班

这些信息会影响自动排班逻辑：

- 工作日：安排晚班
- 周末：安排白班 / 全天值班
- 法定假日 / 休息日：安排节假日值班
- 调休补班：按工作日晚班处理

---

### 🩺 请假记录与冲突检测

支持添加请假记录：

- 请假人员
- 开始日期
- 结束日期
- 请假原因

如果某个请假人员仍然被安排值班，系统会在日历中提示冲突。

---

### ⚠️ 一键修复冲突

当出现以下情况时，可以使用冲突修复功能：

- 值班人员当天请假
- 值班人员已停用
- 导入排班后产生请假冲突
- 自动排班后仍有异常

点击：

```text
⚠️ 修复冲突
```

系统会尝试自动替换为其他可排班人员。

如果没有合适人员，系统会清空该日排班，等待人工处理。

---

### 📥 导入排班 / 恢复备份

支持多种导入方式：

- 上传 JSON 备份
- 上传 CSV / TXT 文件
- 从 WPS / Office / Excel 复制表格粘贴
- 导入 CSV 排班表
- 自动识别 UTF-8 / GBK / GB18030 编码
- 纯净版首次导入时可自动创建人员

推荐导入表格格式：

```text
日期,星期,日期类型,班次,值班人员,时间,备注
```

示例：

```text
2026/5/6,星期二,工作日,工作日晚班,郑楠,18:00-21:00,
2026/5/7,星期四,工作日,工作日晚班,林峰,18:00-21:00,
2026/5/8,星期五,工作日,工作日晚班,赵磊,18:00-21:00,
2026/5/9,星期六,调休上班日,调休上班晚班,孙丽,18:00-21:00,5月9日周六调休上班
```

导入模式支持：

- 合并导入，只覆盖同日期排班
- 清空当前月份后导入
- 仅学习顺序，不导入实际排班

CSV 适合：

## 🔔 飞书 / 钉钉推送配置

### 为什么要用 Cloudflare Worker？

不建议浏览器直接请求飞书 / 钉钉 Webhook。

原因：

1. 浏览器可能有跨域限制
2. Webhook 写在前端不安全
3. 不方便管理推送格式
4. 不适合公开发布到 GitHub

推荐使用 Worker 中转。

---

### Worker 需要配置的 Secret

在 Cloudflare Worker 中配置：

```text
PUSH_TOKEN
FEISHU_WEBHOOK
DINGTALK_WEBHOOK
```

只用飞书时：

```text
PUSH_TOKEN
FEISHU_WEBHOOK
```

只用钉钉时：

```text
PUSH_TOKEN
DINGTALK_WEBHOOK
```

---

### 排班表中填写

点击顶部：

```text
🔔 推送
```

填写：

```text
推送中转接口地址
推送平台
推送口令
推送格式
人员变动自动提醒
```

说明：

| 配置项 | 含义 |
|---|---|
| 推送中转接口地址 | Cloudflare Worker 地址 |
| 推送平台 | 飞书 / 钉钉 |
| 推送口令 | Worker 中设置的 PUSH_TOKEN |
| 推送格式 | 普通文本 / 表格文本 / Markdown 表格 / 飞书卡片表格 |
| 人员变动自动提醒 | 人员修改后是否自动推送 |

## 🔐 数据安全说明

本工具默认使用浏览器本地存储，也就是 `localStorage`。

这意味着：

```text
数据保存在当前浏览器里
不是云端数据库
不会自动同步到其他电脑
```

可能导致数据丢失的情况：

- 清理浏览器缓存
- 更换浏览器
- 更换电脑
- 使用无痕模式
- 系统重装
- 手动重置数据

建议：

```text
每次正式排班前导出 JSON 备份
每次正式排班后导出 JSON 备份
重要修改前先备份
```

## ❓ 常见问题

### 1. 打开后为什么没有人员？

纯净开源版默认不创建示例人员，需要自行添加或导入。

---

### 2. 数据保存在哪里？

保存在当前浏览器本地。

不是云端数据库，不会自动同步到其他电脑。

---

### 3. 换电脑后数据还在吗？

不在。

需要先在旧电脑导出 JSON 备份，再在新电脑导入恢复。

---

### 4. 为什么 WPS / Excel 导入失败？

建议检查是否包含以下列：

```text
日期
班次
值班人员
```

推荐整理成：

```text
日期,星期,班次,值班人员,备注
```

---

### 5. 为什么 CSV 中文乱码？

可能是 WPS 导出的 CSV 使用了 GBK / ANSI 编码。

新版会尽量自动识别 GBK / GB18030。  
如果仍然异常，建议在 WPS 中另存为：

```text
CSV UTF-8
```

---

### 6. 为什么上传 xlsx 不能直接导入？

`.xlsx`、`.xls`、`.et` 不是普通文本文件。  
建议先在 WPS / Excel 中另存为 CSV 后再导入。

---

### 7. 为什么自动排班不符合预期？

请检查：

- 是否已添加人员
- 人员是否处于在岗状态
- 是否导入节假日
- 是否添加请假记录
- 是否学习过旧排班顺序
- 自动排班方式是否选择正确

---

### 8. 为什么推送失败？

可能原因：

- Worker 地址填写错误
- PUSH_TOKEN 填写错误
- Worker 未部署成功
- 飞书 / 钉钉 Webhook 未配置到 Worker Secret
- 机器人安全设置限制关键词
- 网络无法访问 Worker

---

### 9. 可以多人一起使用吗？

当前版本不是真正的多人协同系统。

它更像是：

```text
可以在线打开的本地排班工具
```

每个人浏览器里的数据可能不同。

如果需要多人协同，需要后续接入云数据库、登录系统和权限管理。

---

### 10. 可以在国产系统上用吗？

可以。

银河麒麟、统信 UOS 等系统，只要可以运行现代浏览器，一般都可以使用。
